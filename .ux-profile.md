# UX Profile

Generated by `setup-ui-ux-skills` (2026-10-06). All UI/UX skills in this project read this file before changing layout, copy, or interaction.

## Aesthetic reference

- **Standard:** Apple Native
- **Notes:**
  - Context: a field-ops tool. Used one-handed on an iPhone, outdoors, between doors and in the van. Admin is also used at a desk (1440).
  - Map-first screens behave like Apple Maps: full-bleed map, floating controls on solid surfaces, bottom sheets with detents (peek / half / full).
  - One type family: Sora, using the `field/*` text styles. Hierarchy comes from size and weight, never from extra fonts or colours.
  - Surfaces: d2d tokens only (`field-bg`, `surface`, `line`, `ink`, `ink-muted`, `prop`). Elevation = 1px `line` border first, soft shadow only for things that float over the map.
  - Radii unified: 8 / 12 / 16 / full. Nested radii are concentric.
  - Numbers use tabular figures. Data rows are dense but calm: no zebra stripes, no boxed cells.
  - Colour carries meaning only: `prop` blue = action / selection; outcome colours = Map style v1 (`OUTCOME_DOT`). No decorative colour.
  - Light and dark (Dark token mode 54:0) from day one; dark redeclares `--color-*` under the theme selector, no `dark:` classes.

## Banned anti-aesthetics

- Glassmorphism / `backdrop-filter` without a high-contrast boundary (map overlays use solid `surface` + shadow, never blur)
- Floating pastel pill badges for ordinary metadata (pills only for live state: Out, Due, Live)
- Arbitrary decorative gradients and neon glowing borders
- Multi-colour radial / rainbow gradients on CTAs
- Cartoon empty-state illustrations (people waving / high-fiving)
- Nested scrollbars and icon bloat inside inputs
- Project-specific: the old admin "worksheet" palette, Bricolage / Instrument / Martian Mono, mono uppercase button grids

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:** 4.5:1 normal text, 3:1 large text, borders and map controls. Check both Light and Dark modes. Outcome colours never carry meaning alone (pair with a label or legend).
- **Touch / focus:** 44×44px minimum targets (`size/tap-min`). Visible 2px `prop` focus ring with offset. Overlays (drawer, sheets) trap focus and restore it on close. Respect `prefers-reduced-motion`.

## Brand tone and microcopy voice

- **Voice:** Utilitarian & Minimal
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:**
  - British English.
  - Buttons name the result: "Allocate Tom and Ada · Fri 2 Oct", "End 21 visits", "Save prop".
  - Use the team's words: prop, visit, contacts (bookable only), doors answered (broad), lead, Not in.
  - No explanatory paragraphs on screen. One line of help at most.
  - Errors say what happened and what to do next, never blame the user.
  - No resident names anywhere. Doors are identified by address label or UPRN only.

## Icon library

- **Library:** Project SVG
- **Package / path:** `components/field/icons.tsx`
- **Notes:** Inline SVG, `currentColor`, 24px grid, stroke ~1.7, round caps and joins. New admin icons (menu, draw, undo, redo, layers, calendar, people, settings, chevrons) are added to this file in the same style. No icon package, no emoji.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
